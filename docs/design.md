# 設計

## 0. 方針
- 最初の目標は、decisions.md の15枚のデッキで試験を最後まで動かすこと。  
- 今の15枚で使わない状態異常(不調、スランプなど)は、まだ作らない。ただし、後から足せる形にしておく。  
- 「変わらないもの(カードの定義)」と「変わるもの(ゲームの状態)」を分ける。  
  - AI が「この手を打ったらどうなるか」を試すとき、ゲームの状態だけをコピーすればよくなるため。  

## 1. データ

### 1-1. カードの定義 CardDef(変化しない)
カード1種類につき1つ作る。無印版と+版の両方をここに持たせる。  

| 属性 | 型 | 説明 |
|---|---|---|
| id | 文字列 | cards.csv の id(例: sense_050) |
| name | 文字列 | カード名 |
| plan | 文字列 | free / sense / logic / anomaly |
| type | 列挙 | アクティブ / メンタル / トラブル |
| once_per_lesson | 真偽 | レッスン中1回か(使用後に除外へ移動する) |
| no_duplicate | 真偽 | 重複不可か(デッキを作るときに使う) |
| base | CardVersion | 無印版 |
| plus | CardVersion | +版 |

#### CardVersion(無印版・+版それぞれの中身)
| 属性 | 型 | 説明 |
|---|---|---|
| cost_type | 列挙 | normal(元気→体力)/ hp(体力のみ)/ good_condition / concentration など |
| cost | 整数 | コストの値 |
| use_conditions | UseCondition の配列 | 使用条件(例: 好調状態の場合使用可) |
| effects | Effect の配列 | 効果の部品。effects.csv の order の順に並べる |

#### +の扱い
- 値を書き換えるのではなく、「無印版と+版のどちらを見るか」を切り替える。  
  - カードの定義は1つのまま、デッキの中のカード1枚(DeckCard)が「+かどうか」だけを持つ。  
- 値を書き換えない理由:  
  - 同じカードが2枚あるとき、定義を書き換えると、強化していないもう1枚まで変わってしまう。  
  - 「レッスン中強化」のように、試験の途中で+になる効果がある。DeckCard の plus を true にするだけで済む。  

### 1-2. 効果の部品 Effect
effects.csv の1行。カードの効果を「・」で区切った1つ分。  

| 属性 | 型 | 説明 |
|---|---|---|
| kind | 列挙 | param(パラメータ)/ genki(元気)/ good_condition(好調)/ concentration(集中) |
| value | 整数 | 数値 |
| times | 整数 | 何回発動するか(試行錯誤は2) |
| concentration_rate | 小数 | 集中を何倍で足すか(ハイタッチは1.5、それ以外は1) |
| condition | 列挙 | この部品が発動する条件(none / good_condition) |

### 1-3. 使用条件 UseCondition
| 属性 | 型 | 説明 |
|---|---|---|
| kind | 列挙 | good_condition(好調状態の場合使用可) |

### 1-4. デッキの中のカード1枚 DeckCard
同じカードでも、1枚ごとに別々に作る。  

| 属性 | 型 | 説明 |
|---|---|---|
| uid | 整数 | 試験の中で1枚ごとに違う番号(0〜14) |
| card_id | 文字列 | どの CardDef か |
| plus | 真偽 | +かどうか |

- 効果の値(パラメータ、好調など)はここには持たない。card_id と plus から CardDef を見て取り出す。  

### 1-5. バフ・デバフ Buff
「何の効果が、どれだけの強さで、あと何ターン続くか」を1つにまとめる。  

| 属性 | 型 | 説明 |
|---|---|---|
| kind | 列挙 | 効果の種類(例: param_up = パラメータ上昇量増加) |
| value | 整数 | 強さ(例: 40 なら40%) |
| turns | 整数 | 残りターン数。-1 は試験の最後まで続く |
| fresh | 真偽 | プレイヤーの操作中に付いたか(rules.md のとおり、付いたターンの終了時には減らさない) |

- 例: 「パラメータ上昇量増加40%(3ターン)」→ `{kind: param_up, value: 40, turns: 3, fresh: true}`  
- State は Buff の配列を持つ。同じ種類のバフが別々の強さ・ターン数で複数あっても管理できる。  
- 好調・集中・元気は、State の整数で持つ(Buff の配列には入れない)。  
  - 好調は「残りターン数そのもの」が値。集中と元気はターン数がなく、値だけを持つ。  
  - 一番よく使うので、配列から探さずにすぐ読めるようにする。  
- 今の15枚では Buff の配列は使わない。後から足すときのための入れ物。  

### 1-6. 試験の設定 Exam
| 属性 | 型 | 説明 |
|---|---|---|
| max_turn | 整数 | ターン数 |
| max_hp | 整数 | 最大体力 |
| start_hp | 整数 | 開始時の体力 |
| score_bonus | 小数 | スコアボーナス(最初は1.0で計算する) |

- ターンごとの属性(Vo / Da / Vi)は、確認できてから追加する。  

### 1-7. ゲームの状態 State(変わるもの)
| 属性 | 型 | 説明 |
|---|---|---|
| turn | 整数 | 今何ターン目か(1から) |
| hp | 整数 | 体力 |
| genki | 整数 | 元気 |
| good_condition | 整数 | 好調の残りターン数(0なら好調ではない) |
| perfect_condition | 整数 | 絶好調の残りターン数(0なら絶好調ではない) |
| concentration | 整数 | 集中 |
| score | 整数 | スコア |
| uses_left | 整数 | このターンにあと何枚カードを使えるか(基本1) |
| buffs | Buff の配列 | ターン数つきのバフ・デバフ |
| cards | DeckCard の配列 | デッキの全15枚。uid の順に並べる |
| deck | uid の配列 | 山札(先頭が次に引くカード) |
| hand | uid の配列 | 手札 |
| discard | uid の配列 | 捨て札 |
| exile | uid の配列 | 除外 |

- 山札・手札・捨て札・除外には、カードそのものではなく uid だけを入れる。  
  - 1枚のカードは、必ずどれか1か所にだけある。  
- 乱数(シャッフル用)は State には入れず、関数に外から渡す。  
  - 同じシード値を使えば、同じ試験を何度でも再現できる。  

## 2. 関数

| 関数 | 入力 | 出力 | やること |
|---|---|---|---|
| load_cards | cards.csv のパス | CardDef の一覧(id で引ける) | カードの基本情報を読む |
| load_effects | effects.csv のパス、CardDef の一覧 | なし | 効果と使用条件を CardDef に入れる |
| load_deck | デッキ csv のパス、CardDef の一覧 | DeckCard の配列 | 枚数分の DeckCard を作り、uid を振る |
| init_state | DeckCard の配列、Exam、乱数 | State | 全カードを山札に入れてシャッフルする |
| start_turn | State、乱数 | なし | ドロー枚数を決めて引く。uses_left を1にする |
| draw | State、枚数、乱数 | なし | 1枚ずつ引く。山札が空なら捨て札をシャッフルして山札にする |
| legal_actions | State | 行動の一覧 | 使えるカードの uid と「休む」を並べる |
| can_use | State、uid | 真偽 | 使用条件とコストを払えるかを確認する |
| pay_cost | State、CardVersion | なし | コストを払う(元気→体力の順) |
| calc_param | State、Effect | 整数 | パラメータ上昇量を計算する(下の「パラメータ上昇量の計算」を参照) |
| apply_effect | State、Effect | なし | 効果の部品を1つ発動する |
| use_card | State、uid | なし | コスト → 効果 → カードの移動 → uses_left を1減らす |
| rest | State | なし | 体力+2(最大体力を超えない) |
| end_turn | State | なし | 手札を捨て札へ、バフを減らす、ターンを進める |
| is_end | State、Exam | 真偽 | 最終ターンが終わったか |

### パラメータ上昇量の計算(calc_param)
1. 集中の部分 = 切り上げ(集中 × concentration_rate)  
2. カードのパラメータ値(最終) = value + 集中の部分  
3. 倍率 = 好調がなければ 1、好調だけなら 1.5、好調と絶好調があれば 1.5 + 0.1 × 好調のターン数  
4. パラメータ上昇量 = 切り上げ(カードのパラメータ値(最終) × 倍率)  
- 1 の切り上げは、レッスンでの確認結果による(rules.md を参照)。  
- 小数の誤差で切り上げがずれないように、計算は整数でできる形にする(例: 倍率を10倍した整数で計算してから10で割る)。  

## 3. 1ターンの流れ

1. ターン開始(start_turn)  
   - ドローする枚数を決める。基本は3枚、ドロー枚数を増減する効果があれば足し引きする。  
   - 引く枚数が0を下回る場合は0にする。  
   - uses_left を1にする。  
2. カードを引く(draw)  
   - 1枚ずつ、次の順で引く。  
     1. 山札が空なら、捨て札をすべて山札に移してシャッフルする。  
     2. それでも山札が空なら、引かずに終わる。  
     3. 手札が上限(5枚、要確認)なら、引かずに終わる。  
     4. 山札の先頭を手札に移す。  
   - 手札は長さが変わる配列にする。空きを0で埋める方法は使わない。  
     - 0を「カードがない」の印にすると、手札を扱うすべての処理で0を避ける必要が出てくるため。  
3. 行動を選ぶ(legal_actions)  
   - 手札のうち、can_use が真のカードだけを選べるようにする。  
   - 休むはいつでも選べる。  
   - 休むを選んだら、体力を2回復して 6 に進む。  
4. カードを使う(use_card)  
   1. コストを払う。  
   2. 効果の部品を order の順に発動する。部品に条件があれば、発動する直前に確認する。  
   3. カードを移動する。レッスン中1回なら除外へ、それ以外は捨て札へ。  
   4. uses_left を1減らす。  
5. uses_left が残っていれば 3 に戻る。0なら 6 に進む。  
6. ターン終了(end_turn)  
   - 使わなかった手札を捨て札に移す(要確認)。  
   - 好調のターン数を1減らす。Buff は、fresh でないものだけ turns を1減らし、0になったら消す。fresh のものは fresh を false にする。  
   - turn を1増やす。max_turn を超えたら試験終了。  

## 4. CSV の読み込み

### 読む順番
1. cards.csv:全カードの基本情報を読み、id で引ける一覧を作る。  
2. effects.csv:id で cards.csv のカードを探し、効果と使用条件を入れる。  
3. デッキの csv:id で cards.csv のカードを探し、count の数だけ DeckCard を作る。  

- 後のファイルが前のファイルの id を参照するので、この順番になる。  
- 列は位置ではなく、1行目の列名で探す。列の順番を入れ替えても動くようにするため。  
- cards.csv は、カンマを含む値が `"` で囲まれているので、`"` の中のカンマでは区切らない。  
- 1行目が BOM(ファイル先頭の見えない文字)で始まる場合は取り除く。  
- 行末の `\r` は取り除く(Windows の改行対策)。  

### effects.csv に足す列
- `plus`(no / yes)を追加して、無印版と+版の効果を書き分けられるようにする。今の15枚は全部 no。  

### エラーにする条件
エラーが出たら、ファイル名・行番号・理由を表示して止める。  
- デッキや effects.csv の id が cards.csv にない  
- デッキに入れたカードの効果が effects.csv に1行もない  
- kind や condition が知らない文字列  
- 数値の列が数値として読めない  
- 列の数が1行目と合わない  
- 重複不可のカードがデッキに2枚以上ある  

## 5. 確認用の例
スコアボーナスは1.0として計算する。  

| 例 | 使う前の状態 | 使うカード | 期待する結果 |
|---|---|---|---|
| 1 | 体力30、元気0、好調0、集中0 | アピールの基本 | 体力26、スコア+9 |
| 2 | 体力30、元気2、好調0、集中0 | アピールの基本 | 元気0、体力28、スコア+9 |
| 3 | 好調2、集中3 | ハイタッチ | 切り上げ(3 × 1.5) = 5、(17 + 5) × 1.5 = 33 → スコア+33 |
| 3b | 好調10、絶好調4、集中1 | ハイタッチ | 切り上げ(1 × 1.5) = 2、(17 + 2) × 2.5 = 47.5 → 切り上げて スコア+48(レッスンで確認済み) |
| 4 | 好調0 | 挑戦 | 使えない(legal_actions に出てこない) |
| 5 | 好調0 | 勢い任せ | スコア+6、集中は増えない |
| 6 | 好調1 | 勢い任せ | スコア+9(6 × 1.5)、集中+3 |
| 7 | 好調2、集中1 | 試行錯誤 | 1回目 (8+1)×1.5=13.5→14、2回目も14、スコア+28 |
| 8 | 体力29、最大体力30 | 休む | 体力30(最大体力を超えない) |

- 例7は「2回それぞれで切り上げる」と考えた場合の値。2回目は1回目と同じ状態で計算する。
